# Monitor-Executor — 监控执行

## 目标

把 strategy-maker 生成的策略脚本**跑起来**，持续监控市场，当脚本输出买/卖信号时，经过风控检查后执行交易。

**核心公式：** `策略脚本运行 → 信号 → 风控检查 → 执行/拦截`

---

## 触发条件

当用户表达以下意图时激活本 Skill：

- "把这个策略跑起来"
- "部署监控，不自动下单"
- "开始实盘交易"
- "今天为什么没有信号？"
- "停止所有交易！"
- "信号来了，能执行吗？"
- 任何涉及策略运行、信号监控、交易执行的请求

---

## 输入

| 输入项 | 是否必须 | 说明 |
|--------|---------|------|
| 策略脚本 | **必须** | strategy-maker 生成的 `.py` 或 `.ts` 脚本 |
| 运行模式 | **必须** | `monitor`（只看不做）或 `live`（看了就做） |
| 部署方式 | **必须** | `local`（本地跑）或 `server`（服务器跑） |
| 检查间隔 | 可选 | 多久跑一次脚本（默认跟策略时间周期一致） |
| 风控参数 | 可选 | 日内亏损上限、最大仓位比例、杠杆上限等 |

---

## 输出

| 输出项 | 说明 |
|--------|------|
| 信号通知 | 脚本输出买/卖信号时通知用户 |
| 风控结果 | 信号是否通过风控检查 |
| 执行记录 | 实际下单的详情（仅 live 模式） |
| 运行状态 | 脚本是否在正常运行、资源占用情况 |
| 无信号解释 | 当用户问"为什么没信号"时，解释哪些条件没满足 |

## 两种部署方式

### 方式 1：本地运行 (local)

策略脚本在用户自己的电脑上运行。

**优点：**
- 数据不出本地，隐私性好
- 无需依赖外部服务
- 免费

**缺点：**
- 占用本地 CPU / 内存
- 电脑关机就停了
- 网络不稳定可能影响数据拉取

**运行方式：**

```bash
# 定时运行（每 4 小时执行一次）
# crontab / 系统定时任务
0 */4 * * * cd /path/to/strategy && python my_strategy.py live

# 持续运行（脚本内置循环）
python my_strategy.py live --interval 4h

# 一次性检查（手动触发）
python my_strategy.py live --once
```

**资源预估：**

| 策略类型 | CPU | 内存 | 说明 |
|---------|-----|------|------|
| 纯技术指标 | < 5% | < 100MB | 很轻量 |
| 技术 + 社媒 | 5-15% | 100-300MB | API 调用频繁 |
| 复杂混合策略 | 10-30% | 200-500MB | 多数据源并行 |

### 方式 2：服务器运行 (server)

策略脚本上传到服务器，通过 API 接口执行。

**优点：**
- 不占用本地资源
- 7×24 小时运行
- 不怕断电断网

**缺点：**
- 需要服务器支持
- 脚本代码需要上传（隐私）
- 可能有使用限制

**调用方式：**

```
POST /api/v1/strategy/run
{
  "script": "<脚本内容或脚本ID>",
  "mode": "live",
  "interval": "4h",
  "params": { ... }
}
```

服务器返回信号后，monitor-executor 处理后续的风控和执行。

## 工作流程

### 第 1 步：加载策略脚本

1. 读取策略脚本文件
2. 检查脚本是否实现了标准接口（`generate_signals()`）
3. 安装必要的依赖
4. 确认数据源可访问

### 第 2 步：定时执行

按照设定的间隔运行策略脚本：

```
每个周期:
  1. 执行脚本 → 获取信号输出
  2. 解析信号 JSON
  3. 如果有 buy/sell 信号 → 进入风控检查
  4. 如果无信号 → 记录日志，等待下个周期
```

### 第 3 步：风控检查

每个信号在执行前必须通过以下检查：

| 检查项 | 说明 | 触发条件 |
|--------|------|---------|
| **Kill Switch** | 一键停止所有交易 | 用户手动激活 |
| **日内亏损上限** | 今天亏了多少 | 超过设定阈值（默认 2%） |
| **最大仓位** | 单笔/总仓位是否超限 | 超过设定比例（默认 15%） |
| **杠杆限制** | 杠杆是否过高 | 超过设定上限（默认 10x） |
| **最大回撤** | 从高点回撤了多少 | 超过设定阈值（默认 10%） |
| **冷却期** | 上次交易后是否过了冷却时间 | 短时间内重复交易 |
| **保证金充足** | 余额是否够开仓 | 可用余额不足 |
| **连续亏损** | 是否连续亏损多次 | 连续亏损超限（默认 5 次） |
| **信号有效性** | 信号是否过期 | 信号超过 TTL |
| **重复信号** | 是否重复下单 | 同方向重复信号 |
| **关联性** | 是否同类资产过度集中 | BTC/ETH 等高关联标的 |

### 第 4 步：执行或拦截

**通过风控 → 执行（live 模式）或通知用户（monitor 模式）：**

```
✅ 信号通过风控
   → [live 模式] 自动下单 → 记录交易
   → [monitor 模式] 通知用户 → 等待用户手动确认
```

**未通过风控 → 拦截 + 解释原因：**

```
❌ 信号被拦截
   → 告知用户被哪项风控拦住了
   → 给出建议（等明天 / 减小仓位 / 降低杠杆）
```

### 第 5 步：无信号解释

当用户问"为什么没有信号"时，回溯策略脚本的条件判断过程：

```
📋 BTCUSDT 无信号原因：

  条件 1: MACD 金叉
    当前: DIF=120, DEA=125 → DIF < DEA ❌ 未满足

  条件 2: 成交量放大（> 20日均量 × 1.5）
    当前: 成交量 45000, 均量 60000 → ❌ 未满足

  条件 3: RSI < 70
    当前: RSI=58 → ✅ 满足

  结论: 3 个条件中 2 个未满足，暂无买入信号。
```

## Kill Switch — 紧急停止

用于极端行情下一键停止所有交易活动。

**激活方式：**
- 用户手动："停止所有交易！"
- 自动触发：账户回撤超过预设阈值

**激活后效果：**
- 所有新信号被自动拒绝
- 现有定时任务暂停执行
- 不会影响已有持仓（不会自动平仓）
- 记录激活原因和时间

**关闭方式：**
- 用户手动："恢复交易"
- Kill Switch 不会自动关闭，必须人工操作

---

## 禁止事项

| 禁止行为 | 原因 |
|---------|------|
| ❌ 修改策略脚本 | 修改策略是 strategy-maker 的职责 |
| ❌ 跳过风控检查 | 所有信号必须过风控 |
| ❌ Kill Switch 激活时继续交易 | 紧急停止意味着全部暂停 |
| ❌ 未经用户确认在 monitor 模式下自动下单 | monitor 模式只看不做 |
| ❌ 静默吞掉执行错误 | 任何执行异常必须通知用户 |
| ❌ 在脚本执行失败时重试超过 3 次 | 避免无限循环调用 |
