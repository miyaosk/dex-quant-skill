## 与现货回测的核心差异

| 维度 | 现货/A 股回测 | 永续合约回测 |
|------|-------------|-------------|
| 资金模式 | 全额交割 | 保证金交易 |
| 方向 | 仅做多 | 多空双向 |
| 费率 | 无 | 每 8 小时资金费率结算 |
| 爆仓 | 不存在 | 保证金率不足时强制平仓 |
| 交易时间 | 交易所交易时段 | 24/7 无休 |
| 杠杆 | 无 | 1x-125x |

## 开仓流程

以"BTC 多单 5x 杠杆 数量 1 BTC"为例的完整流程：

```
1. 开仓指令: BTC 多单, 5x 杠杆, 1 BTC

2. 计算初始保证金:
   仓位价值 = 1 BTC × $60,000 = $60,000
   初始保证金 = $60,000 / 5 = $12,000

3. 检查可用保证金:
   账户余额 >= $12,000 ?
   ├─ 是 → 开仓成功，扣除保证金 + 手续费
   └─ 否 → 开仓失败，余额不足

4. 开仓成功后:
   - 账户余额 -= $12,000（保证金）
   - 账户余额 -= $60,000 × 0.05%（Taker 手续费 = $30）
   - 记录: 开仓均价 = $60,000, 杠杆 = 5x
   - 计算强平价格 = $60,000 × (1 - 1/5 + 0.5%) = $49,500
```

## 持仓监控流程

每个 bar 执行以下检查：

```
对每个持仓:
  │
  ├─ 计算未实现盈亏
  │   多单: PnL = 数量 × (标记价格 - 开仓均价)
  │   空单: PnL = 数量 × (开仓均价 - 标记价格)
  │
  ├─ 检查资金费率结算（00:00/08:00/16:00 UTC）
  │   是结算时刻 → 计算并扣除/增加资金费用
  │
  ├─ 计算保证金率
  │   保证金率 = (保证金余额 + 未实现盈亏) / 仓位名义价值
  │
  ├─ 保证金率 < 维持保证金率?
  │   ├─ 是 → 触发强制平仓，记录强平事件
  │   └─ 否 → 继续持仓
  │
  ├─ 检查止损单
  │   标记价格触及止损价? → 市价平仓
  │
  └─ 检查止盈单
      标记价格触及止盈价? → 市价平仓
```

## 核心计算公式

### 保证金计算

```
初始保证金     = 仓位名义价值 / 杠杆倍数
维持保证金     = 仓位名义价值 × 维持保证金率
仓位名义价值   = 数量 × 标记价格
```

### 盈亏计算

```
未实现盈亏（多） = 数量 × (标记价格 - 开仓均价)
未实现盈亏（空） = 数量 × (开仓均价 - 标记价格)
```

### 保证金率

```
保证金率 = (保证金余额 + 未实现盈亏) / 仓位名义价值
```

### 强平价格

```
强平价格（多/逐仓） = 开仓均价 × (1 - 1/杠杆 + 维持保证金率)
强平价格（空/逐仓） = 开仓均价 × (1 + 1/杠杆 - 维持保证金率)
```

### 费用计算

```
资金费用   = 仓位名义价值 × 资金费率
开仓手续费 = 仓位名义价值 × 手续费率
```

### 数值示例

```
场景: BTC 多单, 开仓价 $60,000, 杠杆 5x, 数量 1 BTC, 维持保证金率 0.5%

初始保证金 = $60,000 / 5 = $12,000
强平价格   = $60,000 × (1 - 0.2 + 0.005) = $60,000 × 0.805 = $48,300

当 BTC 涨到 $65,000:
  未实现盈亏 = 1 × ($65,000 - $60,000) = +$5,000
  保证金率   = ($12,000 + $5,000) / $65,000 = 26.2%  ✓ 安全

当 BTC 跌到 $49,000:
  未实现盈亏 = 1 × ($49,000 - $60,000) = -$11,000
  保证金率   = ($12,000 - $11,000) / $49,000 = 2.0%  ✓ 仍安全

当 BTC 跌到 $48,300:
  未实现盈亏 = 1 × ($48,300 - $60,000) = -$11,700
  保证金率   = ($12,000 - $11,700) / $48,300 = 0.62% → ≈ 维持保证金率 → 触发强平
```

## 保证金模式

### 逐仓（Isolated）— P0 必须支持

- 每个仓位独立分配保证金
- 强平仅影响当前仓位，其他仓位不受波及
- 最大亏损 = 该仓位分配的保证金
- 适用场景：多币种分散持仓、风险隔离

### 全仓（Cross）— P0 必须支持

- 所有仓位共享账户可用余额作为保证金
- 某仓位亏损可由其他仓位的未实现盈利补充
- 强平阈值更低，但一旦触发影响全账户
- 适用场景：对冲策略、同方向重仓

## 资金费率结算

### 结算规则

| 项目 | 规则 |
|------|------|
| 结算周期 | 每 8 小时（00:00, 08:00, 16:00 UTC） |
| 方向 | `funding_rate > 0`：多头支付空头；`funding_rate < 0`：空头支付多头 |
| 计算 | `funding_fee = position_value × funding_rate` |
| 对账户影响 | 直接从/加到保证金余额 |
| 数据要求 | **必须使用真实历史资金费率数据，不允许模拟/估算** |

### 结算逻辑

```python
def settle_funding(position, funding_rate, current_time):
    """在 00:00/08:00/16:00 UTC 时刻调用"""
    position_value = position.quantity * position.mark_price
    funding_fee = position_value * funding_rate

    if position.side == "long":
        # 正费率多头支付，负费率多头收到
        position.margin -= funding_fee
        return -funding_fee  # 负值=支出
    else:
        # 正费率空头收到，负费率空头支付
        position.margin += funding_fee
        return funding_fee   # 正值=收入
```

### 数值示例

```
BTC 多单, 仓位价值 $60,000, funding_rate = 0.01%
资金费用 = $60,000 × 0.0001 = $6.00（多头支付）

一天 3 次结算: 日费用 ≈ $18
一年: ≈ $6,570（不可忽略的成本！）
```

## 强制平仓逻辑

### 触发条件

```
保证金率 <= 维持保证金率 → 触发强制平仓
```

### 逐仓模式下的强平

1. 每个 bar 检查每个仓位的保证金率
2. 保证金率 <= 维持保证金率 → 该仓位被强平
3. 其他仓位不受影响
4. 强平以当前 bar 的标记价格成交
5. 已实现亏损 ≈ 初始保证金

### 全仓模式下的强平

1. 计算账户整体保证金率：`(全部余额 + 全部未实现盈亏) / 全部仓位名义价值`
2. 整体保证金率不足 → 按亏损最大仓位优先平仓
3. 平仓后重新计算，若仍不足则继续平下一个

### 强平检查逻辑

```python
def check_liquidation(position, account):
    nominal_value = position.quantity * position.mark_price

    if position.margin_mode == "isolated":
        margin_ratio = (position.margin + position.unrealized_pnl) / nominal_value
        if margin_ratio <= position.maintenance_margin_rate:
            liquidate(position)
            record_event("liquidation", position)

    elif position.margin_mode == "cross":
        total_margin = account.available_balance + sum(
            p.unrealized_pnl for p in account.positions
        )
        total_nominal = sum(
            p.quantity * p.mark_price for p in account.positions
        )
        margin_ratio = total_margin / total_nominal
        if margin_ratio <= min(
            p.maintenance_margin_rate for p in account.positions
        ):
            worst = min(account.positions, key=lambda p: p.unrealized_pnl)
            liquidate(worst)
            record_event("liquidation", worst)
```

## 订单类型

| 类型 | 说明 | 成交逻辑 | 优先级 |
|------|------|----------|--------|
| 市价单 | 按当前 bar close 成交 | `fill_price = close × (1 ± slippage)` | P0 |
| 限价单 | 挂单等待触及 | bar 内 high/low 覆盖限价 → 成交 | P0 |
| 止损单 | 标记价格触及止损价 | 触发后以市价成交 | P0 |
| 止盈单 | 标记价格触及止盈价 | 触发后以市价成交 | P0 |
| 跟踪止损 | 动态止损 | 按回撤百分比调整 | P1 |
| 条件单 | 条件触发 | `funding_rate > 阈值` 等 | P1 |

## 持仓操作

| 操作 | 说明 |
|------|------|
| 开多 Open Long | 买入合约做多 |
| 开空 Open Short | 卖出合约做空 |
| 平多 Close Long | 卖出平仓 |
| 平空 Close Short | 买入平仓 |
| 反手 Reverse | 平掉当前方向 + 反向开仓 |
| 加仓 | 同方向增加持仓（均价重算） |
| 减仓 | 部分平仓 |

## 滑点模型

### 固定滑点（P0）

```
买入成交价 = 信号价 × (1 + slippage_bps / 10000)
卖出成交价 = 信号价 × (1 - slippage_bps / 10000)
```

| 资产 | 建议默认滑点 |
|------|-------------|
| BTC/ETH 永续 | 2 bps |
| 其他主流币永续 | 5 bps |
| 小币种永续 | 10-20 bps |

### 成交量加权滑点（P1）

根据下单量占 bar 成交量的比例动态放大滑点。
